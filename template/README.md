# __GAME__-recomp

A native Linux build of *__INTERNAL_NAME__* (__GAMECODE__, version __VERSION__), made by static
recompilation with [N64Recomp](https://github.com/N64Recomp/N64Recomp) and run on
[N64ModernRuntime](https://github.com/N64Recomp/N64ModernRuntime) with the
[RT64](https://github.com/rt64/rt64) renderer.

**This repository contains no game data.** You need your own dump of the game. The build
checks it against this SHA-1:

```
__ROM_SHA1__  baserom.z64
```

> **AI disclosure.** This project was built with AI assistance (Claude Code). Scaffolded by
> the n64-recomp-toolkit's `new-game.sh`.

## Building

Needs the [n64-recomp-toolkit](__TOOLKIT__) built on this machine (`install.sh`, `build.sh`,
`doctor.sh`). `tools/toolkit.env` says where it is; set `N64RECOMP_TOOLKIT` to override.

```sh
git submodule update --init --recursive
ln -s /path/to/your/dump.z64 baserom.z64   # never copied, never committed

tools/split.sh        # splat: split/asm, split/bin, linker script
tools/build_elf.sh    # assemble + link -> build/__TAG__.elf; must rebuild baserom.z64 byte for byte
tools/recomp.sh       # N64Recomp -> RecompiledFuncs/, RSPRecomp -> rsp/
tools/check_recomp.sh # compile-only check of the generated code
tools/build_game.sh   # the runtime shell + generated code -> build/cmake/__EXE__ (clang, Ninja)

build/cmake/__EXE__ --rom /path/to/your/dump.z64   # checked against the hash, stored; later runs need no --rom
```

Everything under `split/asm`, `split/bin`, `RecompiledFuncs/`, `rsp/` and `build/` is derived
from the ROM, so it is gitignored and regenerated by the commands above.

Finding problems in the split (run from the project root with the toolkit's Python,
`$N64RECOMP_TOOLKIT/.venv/bin/python`):

- `tools/find_fallthrough.py`: functions that run off their end into the next one (a bogus
  symbol or file boundary inside a function).
- `tools/find_missing_funcs.py`: functions only reached through pointers in data, which the
  runtime can't find ("Failed to find function at 0x...").

## Runtime shell

`src/main/` and `CMakeLists.txt` come from the toolkit's `shell-template` (first used for
Aidyn Chronicles): an SDL2 window for RT64, SDL audio, a pad and keyboard on port 1, and
`settings.json` (resolution, aspect, MSAA, supersampling, frame rate, texture packs) in
`~/.local/share/__EXE__`, where the stored ROM and saves also live. They are this project's
own files now: change them as the game needs. `src/game/` is for the game: hooks, replaced
functions and libultra stubs.

Debugging aids: `RECOMP_FPS=1` prints game and shown frame rates, `RECOMP_PAD_FILE=<file>`
feeds buttons from a text file (`<hex buttons> <x> <y>`), `RECOMP_DUMP_TEXTURES=<dir>`
dumps every texture for texture packs, `RECOMP_SETTINGS_DIR=<dir>` reads `settings.json`
from elsewhere.
